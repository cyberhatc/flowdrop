# Changelog

All notable changes to FlowDrop are documented here.
Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
versioning: [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.1.0] — 2026-11-07

First public release. Files, folders and text between any two devices on
the same network — no account, no internet, no cloud.

### Added

- Project skeleton for Android, iOS, Windows, Linux and macOS.
- Neon-glow design system (dark/light), radar home, navigation shell.
- Persistent device identity: Ed25519 key pair + self-signed TLS certificate,
  private material in OS secure storage.
- FlowDrop Protocol v1 models, QR payload, path sanitisation, pairing tokens.
- HTTPS transport: `/v1/info`, `/v1/pair`, `/v1/offer`, `/v1/accept`, `/v1/upload`,
  `/v1/status`, `/v1/cancel`, `/v1/text`, `/v1/clipboard`, `/v1/events`.
- Streaming uploads with incremental SHA-256, `.part` files and resume offsets.
- Discovery: UDP beacon + mDNS lookup, manual connect, QR pairing with
  fingerprint pinning and 2-minute one-time tokens.
- Send files/text/folders UI, incoming request dialog, transfer progress,
  history, drag & drop, "show in folder", Open link / Save .txt.
- Clipboard sync with SHA-256 loop prevention, last-20 history list.
- Mobile share targets: Android share sheet ("Send to FlowDrop").
- Visibility modes (Everyone / Trusted only / Hidden) + server quick toggle.
- 3-slide onboarding, keyboard shortcuts, benchmark tool.
- Unit and in-process integration tests, CI workflow (analyze + test) and
  release workflow building Android, Windows, Linux, macOS and iOS-simulator
  artifacts.

### Fixed

- Self-signed certificates generated by `basic_utils` carried a malformed
  Key Usage BIT STRING that BoringSSL rejects (`CANNOT_PARSE_LEAF_CERT`);
  extensions are now omitted because pinning is the trust model.
- Pairing expiry: a token checked for expiry before pruning now correctly
  returns `PairingResult.expired` instead of `.invalid`, and replayed
  tokens return `.used`.

### Known limitations

- CI / release workflows need the GitHub token to include `workflow` scope.
- iOS share extension needs an Xcode target + App Group (documented).
- Windows desktop build needs Developer Mode / Visual Studio on the
  builder machine (CI runners already have it).

## [Unreleased]

### Fixed

- **QR pairing is now bidirectional.** Redeeming a pairing token used to
  update only the trust store on disk, so the device that showed the QR code
  had to be restarted before it could send files back. The server now emits an
  `onPaired` event, the app refreshes its in-memory trust list and radar, and
  both devices can send immediately after one scan. Covered by an end-to-end
  test that pairs over QR and transfers in both directions.
- Paired devices stay reachable: remembered addresses/ports are persisted,
  probed over HTTPS every 10 s (30 s backoff), and tried again after Wi-Fi
  changes or app restarts.
- Large transfers: real progress speed, resume after interruption, staging
  cleanup, long Windows paths, and a 10-minute idle timeout for slow links.
- The trust store is written atomically with a backup, so a crash mid-write no
  longer loses pairings.
- Added a self-hostable relay (`tool/relay_server.dart`) and
  `docs/REMOTE_TRANSFER.md`. Client tunneling is now wired in via
  `lib/core/transport/relay_bridge.dart`: set the same relay URL on both
  devices (Settings -> Remote transfer) and transfers run end to end through
  the relay, with certificate pinning preserved.

### Added

- Screenshots in the README, generated by golden tests.
- Documentation for presence/reconnection, large files and troubleshooting.
